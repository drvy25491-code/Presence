## User Stories и Критерии приёмки
№1
User Stories: Как преподаватель, я хочу видеть в программе возможность отмечать  присутствие, отсутствие и опоздание студентов, чтобы можно было понять всю посещаемость студентов.

Критерии приёмки: На экране занятия для каждого студента из списка группы доступны три кнопки: Присутствовал, Отсутствовал, Опоздал.

Все проставленные статусы сохраняются в локальную базу данных Room

№2
User Stories: Как преподаватель, я хочу создавать и просматривать список учебных групп, чтобы структурировать студентов по их потокам и специальностям.

Критерии приёмки: В приложении есть экран со списком всех добавленных учебных групп, в котором показаны студенты.

№3
User Stories: Как преподаватель, я хочу видеть статистику посещаемости студента.

Критерии приёмки: На экране статистики отображается общее количество занятий, а также число присутствий, опозданий и пропусков.
Статистика автоматически пересчитывается при добавлении новых занятий или изменении статусов в базе данных.

№4
User Stories: Как куратор, я хочу добавлять студентов в учебную группу с указанием фамилии и имени, чтобы формировать актуальный список для переклички.

Критерии приёмки: Внутри выбранной группы доступна форма добавления нового студента.
Система не позволяет сохранить студента, если поля Фамилия или Имя не заполнены.
Реализована возможность удалить или отредактировать данные студента.

№5
User Stories: Как преподаватель, я хочу создавать карточку занятия с указанием даты, дисциплины и темы, чтобы привязывать отметки посещаемости к конкретной паре.

Критерии приёмки: Доступна форма создания занятия с выбором учебной группы, даты проведения, названия дисциплины и темы урока.

№6
User Stories: Как преподаватель, я хочу просматривать историю проведённых занятий и отметок посещаемости по ним, чтобы при необходимости проверять прошлые записи.

Критерии приёмки: При выборе конкретного занятия открывается ведомость с ранее выставленными статусами и комментариями.

## Спринт 3. Занятия и отметка посещаемости

### Работа с занятиями

##### Как преподаватель, я хочу создавать занятие и отмечать студентов, чтобы фиксировать их посещаемость на конкретной паре.

#### Пошаговый сценарий:
1. Преподаватель открывает экран «Создать занятие» (доступен с главного экрана).
2. Выбирает учебную группу из выпадающего списка.
3. Выбирает дату занятия.
4. Вводит название дисциплины и тему урока.
5. Нажимает кнопку «Начать перекличку». Система сохраняет занятие в базу данных и открывает экран «Отметка посещаемости».
6. На экране отображается список студентов выбранной группы. Для каждого студента доступны три кнопки статуса.

### Согласованные статусы посещаемости:
В приложении используются три строго определенных статуса:
* **«Присутствовал»** - студент был на занятии.
* **«Отсутствовал»** - студента не было.
* **«Опоздал»** - присутствовал, но с опозданием.

### Правило одной итоговой отметки:
* На одно занятие для каждого студента может быть установлена только одна итоговая отметка.
* Если преподаватель меняет статус студента до окончательного сохранения, предыдущий выбор перезаписывается.
* После сохранения ведомости в базу данных Room запись фиксируется. При необходимости ее можно изменить, открыв это занятие заново из истории.
* Для каждого студента на занятии можно оставить один необязательный комментарий.

### Критерии приемки:
* Преподаватель может создать занятие, выбрав группу и дату.
* На экране отметки каждому студенту можно назначить один из трех статусов.
* Изменение статуса до сохранения работает корректно.
* Статусы и комментарии сохраняются в базу данных Room.
* Пустой список студентов обрабатывается понятным сообщением.

## Спринт 5. Статистика, фильтрация и надёжность

### Показатели статистики
На экране статистики должны отображаться следующие числовые показатели:
1. **Общее количество занятий** — сумма всех проведённых пар (по которым были сохранены ведомости).
2. **Количество присутствий** — сколько раз студент был отмечен статусом «Присутствовал».
3. **Количество пропусков** — сколько раз студент был отмечен статусом «Отсутствовал».
4. **Количество опозданий** — сколько раз студент был отмечен статусом «Опоздал».

### Согласованные фильтры
Чтобы статистика была полезной, экран должен поддерживать фильтрацию по следующим параметрам:
* **По студенту:** выбор конкретного учащегося (например, чтобы посмотреть, сколько пропусков у него есть).
* **По группе:** выбор учебной группы (например, чтобы посмотреть общую статистику по конкретной группе).
* **По дате:** выбор периода (например, за текущий месяц, за семестр).


### Поведение при отсутствии отметок 
Приложение не должно падать с ошибкой, если данных для отображения нет. Поведение должно быть следующим:
* **Если нет ни одного занятия:** на экране выводится *«Пока что проведённых занятий нет. Создайте занятие и отметьте посещаемость»*.
* **Если выбранный студент ни разу не отмечался:** выводится сообщение *«Для этого студента ещё нет записей о посещаемости»*.
* **Если по выбранному фильтру (например, за вчерашний день) ничего не найдено:** показывается сообщение *«По выбранным параметрам данных не найдено. Попробуйте изменить фильтр»*.
* **Автоматический пересчёт:** при добавлении нового занятия или изменении статуса студента в базе данных Room, статистика на экране должна обновляться автоматически, без необходимости перезапускать приложение.

### Критерии приёмки:
* На экране отображаются все 4 показателя (занятия, присутствия, пропуски, опоздания).
* Работают фильтры по студенту, группе и дате.
* При отсутствии данных появляется понятное текстовое сообщение.
* При изменении статусов в базе данных статистика пересчитывается корректно.
